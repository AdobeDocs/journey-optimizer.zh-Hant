# 忠誠度挑戰許可權 {#loyalty-permissions}

## 概觀 {#overview}

[!DNL Adobe Journey Optimizer]忠誠度使用Adobe Admin Console角色型存取控制(RBAC)來管理使用者存取權。

必須先指派角色，使用者才能執行忠誠度作業。 未獲指派角色的使用者無權存取忠誠服務端點。 將使用者上線至忠誠度之前，請為將使用該服務的每個使用者指派適當的角色。

可直接指派角色給個別使用者，或透過使用者群組進行指派。 [瞭解如何指派角色給使用者](#assign-roles)。

## 建議的角色 {#recommended-roles}

熟客服務提供為&#x200B;**Prod**&#x200B;沙箱預先設定的三個預設角色。 新客戶可以照原樣使用這些角色。

### 熟客方案管理員 {#loyalty-administrator}

**忠誠度管理員**&#x200B;角色提供所有忠誠度功能的完整管理存取權：挑戰、設定、產品目錄和深入分析。

| 權限 | 說明 |
| - | - |
| 管理忠誠度挑戰 | 建立、編輯、刪除、發佈、取消發佈和封存挑戰；觸發歷程產生 |
| 管理忠誠度主要設定 | 建立、編輯和刪除主要組織設定 |
| 管理熟客方案進階設定 | 管理獎勵端點和事件轉換設定，包括對敏感認證值的讀取/寫入存取權 |
| 管理忠誠度產品目錄 | 檢視、匯入及編輯產品目錄專案 |
| 管理忠誠度深入分析 | 檢視深入分析、更新KPI設定，以及觸發深入分析管道 |

### 熟客從業人員 {#loyalty-practitioner}

**熟客從業人員**&#x200B;角色是專為管理完整挑戰生命週期並編輯主要設定的企業所有者所設計。 獎勵設定、事件設定和產品目錄存取為唯讀。 不允許刪除和進階設定寫入。

| 權限 | 說明 |
| - | - |
| 管理忠誠度挑戰 | 建立、編輯、刪除、發佈、取消發佈和封存挑戰；觸發歷程產生 |
| 設定忠誠度主要設定 | 建立及編輯主要組織組態。 不允許刪除 |
| 檢視熟客獎勵設定 | 檢視獎勵設定，包括提供者、定義和代理人。 敏感值會被排除 |
| 檢視熟客方案事件設定 | 檢視事件定義和事件轉換對應 |
| 檢視忠誠度產品目錄 | 檢視產品目錄專案及匯入工作狀態 |
| 開發忠誠度深入分析 | 檢視見解資料並更新insight卡片 |

### 熟客分析師 {#loyalty-analyst}

**忠誠度分析人員**&#x200B;角色提供挑戰、產品目錄和見解的唯讀存取權。 使用此角色進行報告和稽核。

| 權限 | 說明 |
| - | - |
| 檢視忠誠度挑戰 | 檢視挑戰 |
| 檢視忠誠度產品目錄 | 檢視產品目錄專案及匯入工作狀態 |
| 檢視忠誠度深入分析 | 檢視AI產生的insight卡、健康狀態維生素和挑戰效能資料 |

## 預設角色範圍 {#default-role-scope}

>[!IMPORTANT]
>
>預設熟客方案角色的範圍僅限於&#x200B;**Prod**&#x200B;沙箱。

若要授予使用者存取非Prod沙箱（例如測試或開發沙箱）的許可權，請為該沙箱建立自訂角色，並指派與對應預設角色相同的許可權。

## 指派角色給使用者 {#assign-roles}

>[!IMPORTANT]
>
>只有產品管理員和系統管理員可以管理使用者、群組和角色。

Adobe Admin Console支援兩種將角色與使用者建立關聯的方法。

### 將使用者直接指派給角色 {#assign-users-directly}

將個別使用者直接新增至角色。 此方法最適合小型團隊或一次性指派。

### 使用使用者群組 {#use-user-groups}

建立使用者群組，然後將使用者和角色指派給群組。 此方法最適合依部門或職能大規模管理存取權。

如需管理角色、群組和使用者的逐步指示，請參閱Adobe Journey Optimizer存取控制檔案：

* [管理使用者和角色](../administration/permissions.md)
* [內建權限](../administration/ootb-permissions.md)

## 疑難排解存取 {#troubleshooting}

如果使用者無法存取忠誠度挑戰或相關功能，請檢查下列專案：

* 已將使用者指派給忠誠度角色。
* 角色包括啟用忠誠度挑戰的沙箱。
* 角色包含使用者嘗試執行的動作所需的許可權。
* 對於非Prod沙箱，已為該沙箱建立自訂角色。
* 針對忠誠度挑戰啟用組織和沙箱。

如果在更新許可權後存取問題持續存在，請聯絡您的Adobe代表。
